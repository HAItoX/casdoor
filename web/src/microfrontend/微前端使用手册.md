# 微前端使用手册

## 1. 微前端架构概述

### 1.1 架构说明

当前项目采用 **qiankun** 作为微前端框架，实现了主应用与多框架子应用的无缝集成。主应用使用 React 18 开发，支持接入 React、Vue、Next.js、纯 JS 等多种框架的子应用。

### 1.2 核心目录结构

```
src/microfrontend/
├── SubAppContainer.js       # 子应用容器组件
├── auth.js                  # 认证集成逻辑
├── config.js                # 核心配置文件
├── eventBus.js              # 事件总线
└── utils.js                 # 工具函数
```

## 2. 子应用接入流程

### 2.1 配置子应用信息

子应用配置支持两种方式：**本地配置** 和 **服务器配置**。

#### 2.1.1 本地配置

在 `src/microfrontend/utils.js` 中的 `getLocalSubApps()` 函数配置子应用信息：

```javascript
{
  name: "sub-app-react",           // 子应用名称（唯一标识）
  entry: "//localhost:3001",      // 子应用入口地址
  container: "#subapp-container", // 容器选择器
  activeRule: "/subapp/react",    // 激活规则（路由匹配）
  props: {}                        // 自定义属性
}
```

#### 2.1.2 服务器配置

在 `src/microfrontend/utils.js` 中的 `getServerSubApps()` 函数实现从服务器获取配置：

```javascript
export const getServerSubApps = async () => {
  try {
    const response = await fetch('/api/subapps');
    return await response.json();
  } catch (error) {
    console.error("[MicroFrontend] 加载服务器子应用配置失败:", error);
    return [];
  }
};
```

### 2.2 子应用实现要求

无论使用何种框架，子应用都需要实现以下生命周期函数：

```javascript
export async function bootstrap(props) {
  console.log('[SubApp] 初始化:', props);
}

export async function mount(props) {
  console.log('[SubApp] 挂载:', props);
}

export async function unmount(props) {
  console.log('[SubApp] 卸载:', props);
}
```

## 3. 各框架子应用接入指南

### 3.1 React 子应用

#### 3.1.1 修改入口文件 (`src/index.js`)

```javascript
import React from 'react';
import ReactDOM from 'react-dom';
import App from './App';
import './index.css';

function render(props) {
  const { container } = props;
  const root = container ? container.querySelector('#root') : document.querySelector('#root');
  
  ReactDOM.render(
    <React.StrictMode>
      <App {...props} />
    </React.StrictMode>,
    root
  );
}

// 独立运行时
if (!window.__POWERED_BY_QIANKUN__) {
  render({});
}

// 微前端环境下的生命周期函数
export async function bootstrap() {
  console.log('[SubApp-React] bootstraped');
}

export async function mount(props) {
  console.log('[SubApp-React] mounted with props:', props);
  render(props);
}

export async function unmount(props) {
  console.log('[SubApp-React] unmounted');
  const { container } = props;
  const root = container ? container.querySelector('#root') : document.querySelector('#root');
  ReactDOM.unmountComponentAtNode(root);
}
```

#### 3.1.2 修改 `webpack.config.js`

```javascript
const { name } = require('./package.json');

module.exports = {
  output: {
    library: `${name}-[name]`,
    libraryTarget: 'umd',
    jsonpFunction: `webpackJsonp_${name}`,
    publicPath: '//localhost:3001/',
  },
  devServer: {
    headers: {
      'Access-Control-Allow-Origin': '*',
    },
  },
};
```

### 3.2 Vue 子应用

#### 3.2.1 修改入口文件 (`src/main.js`)

```javascript
import Vue from 'vue';
import App from './App.vue';
import router from './router';

Vue.config.productionTip = false;

let instance = null;

function render(props = {}) {
  const { container } = props;
  instance = new Vue({
    router,
    render: (h) => h(App),
  }).$mount(container ? container.querySelector('#app') : '#app');
}

// 独立运行时
if (!window.__POWERED_BY_QIANKUN__) {
  render();
}

// 微前端环境下的生命周期函数
export async function bootstrap() {
  console.log('[SubApp-Vue] bootstraped');
}

export async function mount(props) {
  console.log('[SubApp-Vue] mounted with props:', props);
  render(props);
}

export async function unmount() {
  console.log('[SubApp-Vue] unmounted');
  instance.$destroy();
  instance = null;
}
```

#### 3.2.2 修改 `vue.config.js`

```javascript
module.exports = {
  devServer: {
    port: 3002,
    headers: {
      'Access-Control-Allow-Origin': '*',
    },
  },
  configureWebpack: {
    output: {
      library: 'sub-app-vue',
      libraryTarget: 'umd',
    },
  },
};
```

### 3.3 Next.js 子应用

Next.js 需要使用 `@module-federation/nextjs-mf` 插件：

```bash
npm install @module-federation/nextjs-mf
```

#### 3.3.1 修改 `next.config.js`

```javascript
const withModuleFederation = require('@module-federation/nextjs-mf/withModuleFederation');

module.exports = withModuleFederation({
  name: 'sub-app-next',
  filename: 'static/chunks/remoteEntry.js',
  exposes: {
    './index': './pages/index.js',
  },
  shared: {
    react: {
      singleton: true,
      requiredVersion: false,
    },
    'react-dom': {
      singleton: true,
      requiredVersion: false,
    },
  },
});
```

### 3.4 纯 JS 子应用

#### 3.4.1 创建入口 HTML

```html
<!DOCTYPE html>
<html>
<head>
  <title>纯 JS 子应用</title>
</head>
<body>
  <div id="subapp-js-root"></div>
  <script src="http://localhost:3004/main.js"></script>
</body>
</html>
```

#### 3.4.2 创建 `main.js`

```javascript
// 渲染函数
function render(props) {
  const { container } = props;
  const root = container ? container.querySelector('#subapp-js-root') : document.querySelector('#subapp-js-root');
  root.innerHTML = '<h1>Hello from Pure JS SubApp</h1>';
}

// 独立运行时
if (!window.__POWERED_BY_QIANKUN__) {
  render({});
}

// 微前端环境下的生命周期函数
window['sub-app-js'] = {
  bootstrap: () => {
    console.log('[SubApp-JS] bootstraped');
    return Promise.resolve();
  },
  mount: (props) => {
    console.log('[SubApp-JS] mounted with props:', props);
    render(props);
    return Promise.resolve();
  },
  unmount: () => {
    console.log('[SubApp-JS] unmounted');
    return Promise.resolve();
  },
};
```

## 4. 路由配置

### 4.1 主应用路由

主应用使用 `react-router-dom` 配置路由，子应用通过动态路由 `subapp/:appName*` 进行匹配：

```javascript
<Route path="/subapp/:appName*" component={SubAppContainer} />
```

### 4.2 子应用路由配置

#### 4.2.1 React 子应用

```javascript
import { BrowserRouter } from 'react-router-dom';

function render(props) {
  const { container, basename = '/subapp/react' } = props;
  ReactDOM.render(
    <BrowserRouter basename={basename}>
      <App />
    </BrowserRouter>,
    container ? container.querySelector('#root') : document.getElementById('root')
  );
}
```

#### 4.2.2 Vue 子应用

```javascript
const router = new VueRouter({
  mode: 'history',
  base: window.__POWERED_BY_QIANKUN__ ? '/subapp/vue' : '/',
  routes,
});
```

## 5. 认证集成

### 5.1 子应用获取认证信息

子应用通过 `props` 获取当前认证信息：

```javascript
export async function mount(props) {
  const { account, accessToken, serverUrl } = props;
  console.log('当前用户:', account);
  console.log('访问令牌:', accessToken);
  console.log('服务器地址:', serverUrl);
}
```

### 5.2 认证状态同步

#### 5.2.1 登录成功

子应用可通过 `props.onLoginSuccess` 方法通知主应用登录成功：

```javascript
props.onLoginSuccess(newAccount, newAccessToken, '/dashboard');
```

#### 5.2.2 账户信息更新

子应用可通过 `props.onUpdateAccount` 方法更新账户信息：

```javascript
props.onUpdateAccount(newAccount, newAccessToken);
```

## 6. 事件通信

### 6.1 主应用发送事件

```javascript
import eventBus from './eventBus';

eventBus.emit('loginSuccess', { account, accessToken });
```

### 6.2 子应用监听事件

```javascript
// 在子应用中获取事件总线
const eventBus = window.parent.__QIANKUN_MASTER_EVENT_BUS__;

// 监听事件
eventBus.on('loginSuccess', (data) => {
  console.log('登录成功:', data);
  // 更新子应用的认证状态
});

// 移除事件监听
eventBus.off('loginSuccess', callback);
```

### 6.3 支持的事件列表

| 事件名称 | 触发时机 | 数据结构 |
|---------|---------|---------|
| loginSuccess | 登录成功 | `{ account, accessToken }` |
| logout | 登出 | 无 |
| accountUpdated | 账户信息更新 | `{ account, accessToken }` |
| subAppLoaded | 子应用加载完成 | `{ name }` |
| subAppError | 子应用加载失败 | `{ name, error }` |

## 7. 样式隔离

当前配置已启用 qiankun 的样式隔离功能：

```javascript
// src/microfrontend/config.js
start({
  sandbox: {
    strictStyleIsolation: true,     // 严格的样式隔离
    experimentalStyleIsolation: true, // 实验性样式隔离
  },
});
```

### 7.1 子应用样式注意事项

1. **避免使用全局选择器**：如 `body`, `html` 等
2. **使用 CSS Modules** 或 **BEM 命名规范**
3. **Vue 子应用**：使用 `scoped` 属性
4. **React 子应用**：使用 `CSS Modules` 或 `styled-components`

## 8. 开发与部署指南

### 8.1 开发环境

1. 启动主应用：`npm start`
2. 启动子应用：`npm run dev`（根据子应用框架）
3. 访问子应用：`http://localhost:8080/subapp/[appName]`

### 8.2 部署环境

#### 8.2.1 子应用配置

1. 修改子应用的 `publicPath` 为实际部署地址
2. 确保子应用支持 CORS（配置 `Access-Control-Allow-Origin`）

#### 8.2.2 主应用配置

1. 更新 `src/microfrontend/utils.js` 中的子应用入口地址
2. 配置服务器端 API 提供动态子应用列表（可选）

### 8.3 服务器配置要求

1. **支持 CORS**：子应用服务器需允许主应用跨域访问
2. **静态资源访问**：确保子应用的静态资源可以通过绝对路径访问
3. **路由配置**：子应用服务器需配置 `history` 模式的 fallback 路由

## 9. 常见问题与解决方案

### 9.1 子应用加载失败

**问题**：控制台显示 "Loading chunk [name] failed"

**解决方案**：
- 检查子应用入口地址是否正确
- 确认子应用已启动且端口匹配
- 检查 CORS 配置是否正确

### 9.2 样式冲突

**问题**：子应用样式影响主应用或其他子应用

**解决方案**：
- 确保主应用已启用 `strictStyleIsolation`
- 子应用使用 CSS Modules 或 BEM 命名规范
- 避免使用全局样式选择器

### 9.3 路由跳转异常

**问题**：子应用内部路由跳转失败

**解决方案**：
- 确保子应用路由的 `basename` 配置正确
- 使用 `history` 模式而非 `hash` 模式
- 检查主应用路由配置是否包含通配符 `*`

### 9.4 认证信息不同步

**问题**：子应用获取的认证信息不是最新的

**解决方案**：
- 检查是否正确使用 `props.onLoginSuccess` 和 `props.onUpdateAccount` 方法
- 确保事件监听器正确注册
- 刷新页面重新加载子应用

## 10. 最佳实践

1. **子应用独立性**：子应用应可独立运行，避免强依赖主应用
2. **资源隔离**：避免子应用修改主应用的 DOM 或全局变量
3. **通信规范**：使用事件总线进行通信，避免直接操作主应用状态
4. **性能优化**：
   - 启用 qiankun 的 `prefetch` 功能
   - 子应用使用懒加载
   - 合理设置 `singular` 模式
5. **错误处理**：子应用应实现完善的错误捕获和日志记录
6. **版本管理**：为子应用配置版本号，便于回滚和问题排查
